# ポストプロセッサと工具交換

iwashita NV2 用ポスト（`iwashita_NV2_posts`）で作り込んだ内容と、工具番号の決まり。

## 手動工具交換＋工具長補正の安全シーケンス（ポスト側で作り込む）

ATCが無い／工具を毎回手で交換する運用では、工具交換のたびに「交換 → 工具長測定 → オフセット入力 →
サイクルスタート」という**手動介入**が入る。このとき効くのがポストプロセッサ側の作り込みで、
CAMのオペレーション設定（ラピッド平面等）では手当てできない。

**最大の危険は「復帰直後にXY早送りが来る」こと。** SOLIDWORKS CAMの標準的なポスト構成では
工具交換の後に`RAPID_FROM_TOOL_CHANGE_MILL`（XY早送り）→`FIRST_RAPID_Z_MOVE_DOWN_MILL`（Z位置決め）
の順で出るため、測定のために刃先を下げたまま復帰すると、**工具がワークやクランプを横切る**。

対策は工具交換セクションの末尾、つまりXY早送りの直前に退避を差し込むこと。

```
G91 G28 Z0 / G90 / M05 / X0 Y0    交換前：Z退避・主軸停止・XY原点へ
(工具コメント) / T05 M06
M00                                停止：手で交換 → 工具長測定 → オフセット入力
G91 G28 Z0 / G90 / X0 Y0           ★復帰直後の再退避（手動介入の保険）
G43 Z30. H05                       ★補正込みでワーク原点上空30mmへ
M00                                停止：補正がかかっているか目視確認
（退避せずそのまま本編へ。XY早送りはZ30で行われる）
```

設計上のポイントは4つ。

- **`G91 G28 Z0`は中間点が現在位置になるので真上にZだけ動く。**手でどこに動かした後でも横移動しないため、
  手動介入からの復帰に最適。`G53 G0 Z0`より汎用性が高い
- **`G28`の後はG91がモーダルに残る。**直後に`G90`を明示しないと次の移動が増分になる
- **`G28`は参照点で工具長補正をキャンセルする。**そのため退避のたびに`G43 H○`を出し直す必要がある。
  逆に、補正を効かせたまま上下させたい場面（プログラム末尾の確認移動）では`G28`を使ってはいけない
- **確認移動の高さは、CAM側のラピッド平面以上にする。**確認後のXY早送りはこの高さで行われるため、
  低すぎるとクランプに当たる。逆に十分高くしておけば**確認後の退避が不要**になり、
  Z軸が「上がって降りるだけ」になる。確認後に退避を挟む書き方（降りて上がってまた降りる往復）は
  時間も食い動きも危ないので採らない。
  なお`INIT_TOOL_CHANGE_MILL`の冒頭の退避とXY原点移動は、直前の`START_OF_TAPE`が
  同じことをしているため**一度も動かない無駄な行**だった。これも削除済み

#### 安全退避高さはプログラム全体で1つに統一する（現行 Z30）

工具交換の確認移動・工具交換後のXY早送り・`END_OF_TAPE`のXY横移動と終了位置を、
**すべて同じワーク座標Z（現行は`Z30.`）に揃える**。個別に別の値を置くと、
どこかが「上がってまた降りる」往復になり、どの高さが安全基準なのかも分からなくなる。

```
START_OF_TAPE     G91 G28 Z0      補正が無いので機械原点退避（ここだけ例外・最上位）
工具交換の確認移動   G43 Z30. H○     ★統一高さ
本編のXY早送り      （Z30のまま）     確認移動の高さがそのまま渡りの高さになる
END_OF_TAPE       Z30. → X0 Y0    ★統一高さ。降下させずここで終わる
```

- **決め方は「CAM側のラピッド平面より高く、かつ一番高い障害物より上」。**
  ラピッド平面が25mmなら統一高さは30mm程度。ここを下げるとラピッド平面を下回って意味を失う
- **`END_OF_TAPE`で統一高さより低い位置へ降ろさない。**終了位置を下げても得は無く、
  上げて降りる往復が1回増えるだけ。次プログラムの`START_OF_TAPE`がどのみち機械原点まで上げ直す
- **この統一高さは「刃先基準」であることが前提。**`G43`がモーダルに効いている区間でしか成立しないので、
  補正が無い`START_OF_TAPE`だけは機械原点退避のままにする

### M06で止まる機械でもM00は意図的に残す

この機械はATCが無く、`M06`でプログラムが止まる作りになっている。それでも**シーケンス中の2つのM00は削らない。**

- **M06の停止はメーカー側（PMCラダー）の挙動であって、NCプログラムには書かれていない。** プログラムを
  読んだだけでは「ここで止まる」と分からないし、機械が変わればその保証も消える。安全に関わる停止を
  プログラムの外側の挙動に依存させない
- **先読みが止まる保証もパラメータ依存。** M06で先読みが止まるのは`3411`〜`3420`（バッファリングしない
  Mコード）にM06が登録されている場合だけで、これはNCのメモリ上の設定。メモリクリアやバックアップからの
  復元で戻ると、**プログラムは何も変えていないのに挙動だけが変わる**。しかも失敗の出方が
  「オフセットが効かず刃先が想定より下がる」という最悪の形になる
- **2つ目のM00（`G43 Z50. H○`の直後）は先読みと無関係。** 補正がかかっているかを人間が目視確認するための
  停止なので、M06が何をしようと不要にならない。ここが最後の安全装置（次項）

なお「M完了待ち（FIN待ち）」と「先読み停止」は別物で、**M完了を待っている間もNCは次のブロックを
読んで解釈している**。`G43 Z50. H○`の補正ベクトルはブロック解釈の時点で計算されるため、
先読み済みだと後からオフセットを書き換えても効かない。M00を挟むのはこれを断ち切るためでもある。

代償は工具1本あたりサイクルスタートを1回余分に押すことだけ。

### 確認移動の構造的な弱点（運用でカバーするしかない）

`G43 Z50. H○`は、**Hが0や誤値だとこの行自体が刃先をワークに突っ込ませる**。
「補正がかかっているか確認する動き」が、かかっていないときに最も危険な動きになる。
補正の有無をGコードで検出する手段は無いため、運用で守る。

- 確認移動は**シングルブロック＋ラピッドオーバーライド最低（5%程度）**で通す
- **座標表示のZが統一高さ（現行30.000）付近**であることと、
  **刃先とワーク上面の隙間が目視でその値ある**ことを両方見る

### プログラム開始・終了時の扱い

- **開始時（`START_OF_TAPE`）では補正の確認はできない。**工具交換より前に実行されるため補正値がまだ無い。
  ここは工具長に依存しない`G91 G28 Z0`（機械原点までZ退避）にしておく。
  **`G43`なしでワーク座標の`Z20.`へ動かすのは危険**で、これは「主軸ゲージラインをワークZ+20に置く」意味に
  なり、刃先は工具長分だけ下がってワークに突っ込む（工具1本＋G54のZに工具長を含める運用でだけ成立していた）
- **終了時（`END_OF_TAPE`）は確認できる。**最終工具の`G43`がモーダルに残るので、
  `Z30.`→`X0 Y0`の順で動かせば刃先がワーク原点上空30mm（統一高さ）に来る。
  ここで`G28`を使うと補正が消えて刃先基準でなくなる。
  **この後にさらに低いZへ降ろす行は置かない**（往復になるだけで得が無い）

## ツールクリブの番号とNCコードの対応（2026-09-10に実機用コードで確認済み）

φ12超硬エンドミル＋φ8センタードリルの2工具構成でポスト出力し、実物のNCコードで突き合わせた。

| ツールクリブの欄 | 正体 | NCコードでの出力 |
|---|---|---|
| ID | クリブ登録行のDB内部ID | 出力されない |
| **ステーション番号** | **T番号** | `T05 M06` |
| 補助番号 | 副ステーション番号（タレット機等） | 通常使わない |
| 工具ID | TechDBの工具ライブラリ側のレコード番号 | 出力されない |
| **長さのオフセット** | **H番号（工具長補正）** | `G43 Z20. H05` |
| **直径のオフセット** | **D番号（工具径補正）** | `G41 D25` |
| ゲージX/Y/Zオフセット | 干渉計算・シミュレーション用 | 出力されない |

「工具ID」はデータベース内部の参照番号であり機械とは無関係。**T番号と間違えやすい**。
現場では**T番号=H番号=D番号で揃える**のが安全（段取りミス防止）。

### D番号だけずれる場合はポストの`COMP_OFFSET`を疑う

クリブに登録した覚えのない番号がD番号として出ることがある。**原因はポスト側の加算設定**で、
`.SRC`の`CALC_INIT_CODES`セクションにある下記の1行がD番号にだけ加算される。

```
:C: COMP_OFFSET=20
```

2026-09-10の実例：TechDB上は`直径のオフセット=5`なのにNCコードは`D25`。
`5 + COMP_OFFSET(20) = 25`という計算だった（H番号には加算されないため`H05`のまま）。
**クリブ側をいくら探しても25という数字は存在しない**ので、この設定を知らないと原因に辿り着けない。

FANUC系の古い制御では工具長補正と径補正が**1つのオフセット表を共有**することがあり、
20本マガジンなら「1〜20番＝工具長、21〜40番＝工具径」と住み分ける慣習がある。
ベースのFANUCミル用ポストにこの慣習が残っているのが理由。

対処は機械のオフセット画面の作りで決める。

| 画面の見え方 | 制御のタイプ | 対処 |
|---|---|---|
| 番号ごとに「形状(H)/摩耗(H)/形状(D)/摩耗(D)」の4列 | 補正メモリC（H・Dが独立） | `COMP_OFFSET=0`にしてT=H=Dで揃える |
| 番号ごとに「形状/摩耗」の2列のみ | 補正メモリA・B（共有） | 20のまま。加算後の番号に値を入れる |

**制御の補正個数が加算後の番号に足りているかも確認する**（20個しかない制御に`D25`を出すとアラーム）。

**本環境では2026-09-10に`COMP_OFFSET=0`へ変更し、T番号=H番号=D番号を揃える方針で確定した。**
番号が飛ぶと、普段使わない番号に誰かが入れた値が効いてしまうリスクがあるため。
変更後のポスト出力で`T05`／`H05`／`D05`と揃うことを確認済み。

なお**TechDBの実体はSQLiteデータベース**なので、UIで追えない値は直接クエリして確認できる。
クリブの登録内容は`MchCribTool`テーブル（`StnNo`／`Length_Offset`／`Diameter_Offset`／`KeyParams`）、
クリブ定義とステーション合計数は`MchToolCribDesc`テーブル（`TotalStns`）にある。
**必ずコピーを取ってから読み取り専用で開くこと。**

### 工具番号の割り当て：空いている番号を使う

**学校として決まった番号の割り当てはない。** 共用機なので、**他の使用者が登録した工具と番号が衝突しないこと**だけを守ればよい。

- **0番台・10番台は他の人が使っていることが多い。** 自分の工具は、それより後ろの空いている番号に登録すると運用が楽
- **20〜27番には、2026年度の担当者がよく使う工具を登録してある**（このリポジトリの TechDB のツールクリブも同じ番号）。
  同じ工具を使うならそのまま使ってよい。自分の工具を新しく登録するなら、28番以降などの空いている番号を選ぶ
- 2026-09-16時点で、オフセット表の20番以降はすべて空いていた（その後20〜27番を使用）

上記の`COMP_OFFSET=0`と組み合わせるため、1本の工具に対して`T28`／`H28`／`D28`のように3つとも同じ番号で揃う。

工具を新しく登録するときの確認事項。

- [ ] **ツールクリブのステーション合計数が、使う番号以上あるか。**足りないと大きいステーション番号を
      登録できない。UIで増やせない場合は`MchToolCribDesc`テーブルの`TotalStns`を見る
- [ ] **機械のオフセット表の行数が、使う最大番号以上あるか**（足りない番号を出すとアラームになる）
- [ ] 実機のオフセット画面で、これから使う番号が本当に空かを**番号を起こすたびに**見る
      （共用機なので、他の使用者が後から値を入れている可能性がある）
- [ ] 一度割り当てた番号は、工具を入れ替えても**使い回さない**。同じ番号に違う工具が入ると、
      前の工具の補正値がそのまま効く

**2026-09-17時点の内容**：`Tool Crib 1 (Metric) Empty` はステーション20〜27の8本で、
全ステーションで長さ・直径のオフセットが番号と一致している（T=H=D）。

### ポスト処理のたびに確認すること

- [ ] **作業座標系（G54〜G59）が出力されているか。**【最頻出の抜け】原因はセットアップごとの
      「ワーク座標系オフセット」の設定漏れ。[`02-setup-and-coordinates.md`](./02-setup-and-coordinates.md) の「【毎回必ず確認】ワーク座標系オフセットは
      セットアップごとに設定する」を参照
- [ ] 出力された座標系の番号が意図どおりか（G54とG56の取り違え）
- [ ] **工具交換の確認移動`G43 Z50.`と`END_OF_TAPE`の`Z20.`が、ワーク上面より上を指しているか。**
      これらはワーク原点基準の固定値なので、セットアップの原点Zを上面以外に取ると刃先が材料に突っ込む。
      [`02-setup-and-coordinates.md`](./02-setup-and-coordinates.md) の「原点のZは、そのセットアップの上面に取る」を参照。**シミュレーションでは検出できない**
- [ ] 侵入がらせん／傾斜になっているか（プランジのまま出ていないか）
- [ ] 円弧一致をONにした場合、曲線が`G02`/`G03`で出ているか（直線G01の連続になっていないか）
- [ ] らせん侵入の輪が工具径と同程度の大きさで描かれているか（ツールパスを目視）
- [ ] 以前修正したZ退避・G28・クーラント出力がデグレしていないか
- [ ] **回転数`S`と送り`F`が妥当か。**部品が抱える機械定義が古いと一気に変わる。
      丸い上限値（例：`S12000`）が出たら機械定義の最大主軸回転数でクランプされた疑い
- [ ] 穴あけサイクルの`R`点が、その穴の実際の材料上面と合っているか
      （ポケット底の穴では`R`が負値になる。`R0`と`R-2.`が混在することがある）
