# 切削条件（送り・回転数）と侵入方法

## FANUC MANUAL GUIDE i から来ると戸惑う点：全幅／側面の送り分けが無い

0i-Model F の MANUAL GUIDE i では、全幅（溝）切削と側面（片側だけ）切削で別々の送り速度を
条件として持てるが、**SOLIDWORKS CAMの工具側の切削条件はXY送り速度を1つしか持たない**。
径方向の食い込み量（ae）が全幅だろうが0.5mmだろうが、同じ値が使われる。

**対処：TechDBには安全側＝全幅（溝）基準の条件を登録する。**
軽く削るオペレーションでは、パーツ内のオペレーションパラメータ側で個別に送りを上げる。
逆向き（側面基準で登録して溝加工で下げ忘れる）は工具折損に直結するのでやらない。

補足：「歯ごとのフィード（fz）」と「XY送り速度」は連動しており、片方を変えるともう片方が
再計算される（`fz × 刃数 × 回転数 = XY送り速度`）。**回転数を変えると送りも動く**ので、
条件を触ったあとは両方の値を確認すること。

## 【重要】自動工程生成は「デフォルトの操作パラメータ」を見ていない

**フィーチャからの自動工程生成が参照するのは「フィーチャと操作」のマッピング側であり、
「デフォルトの操作パラメータ」画面で設定した値は使われない。**2026-09-11に実機コードで確定した。

この構造を知らないと、**「デフォルトの操作パラメータ」をいくら設定しても何も変わらない**という
空振りを延々と続けることになる。実際にそうなった。

**確定させた手順**（同じ疑いが出たらこの方法で切り分ける）：

1. オペレーションを全削除し、フィーチャを抽出し直して工程を再生成する
2. それでもNCコードが1文字も変わらなければ、参照元は別にある
3. TechDBの2系統の値をNCコードと突き合わせる

このときの突き合わせ結果（荒加工ミル）：

| | 切り込み | 最終切削量 | クリーンアップパス |
|---|---|---|---|
| **NCコードの実際** | 50% | **0.25mm** | **あり** |
| 「フィーチャと操作」マッピング側（メートル244件） | **50.0%** | **0.25** | **ON** |
| 「デフォルトの操作パラメータ」（設定済み） | 33.3% | 0.5 | OFF |

**マッピング側とNCコードが完全一致。**設定した既定値はどこにも現れなかった。

**テーブルの対応**：`FeaOper1`（フィーチャと操作のマッピング。`Units` 1=メートル/2=インチ、
`OperationID` 7=荒加工ミル/117=輪郭ミル）が、`RghMillFeaOperParams`／`FinishMillFeaOperParams`を
`FeaOperID`＝`ID`で参照する。「デフォルトの操作パラメータ」は`DefPrm`接頭辞の別テーブル。

**「デフォルトの操作パラメータ」が効く場面**：工程を手動で挿入するとき。
自動工程生成を使わず手動で工程を組む運用にすれば、そちらの設定が生きる（部品数が少なければ現実的な選択肢）。

## マッピング側をSQLで一括更新する手順

件数が多くUIでは直せないため、SQLで直接更新する。**SOLIDWORKSとTechDBのUIを完全に終了してから**行い、
**必ず`TechDB.cwdb`のバックアップを取る**（バックアップ先は`SW_CAM_backup\<YYYY-MM-DD>\`）。

2026-09-11に実施した内容（メートル系のみ。インチ系は対象外にした）：

```sql
-- 荒加工ミル・メートル294件
UPDATE RghMillFeaOperParams
   SET FirstCutAmt_Percent = 33.3, SubCutAmt_Percent = 33.3,
       FinCutAmt = 0.5, CleanupPass = 0
 WHERE ID IN (SELECT FeaOperID FROM FeaOper1 WHERE Units = 1 AND OperationID = 7);

-- 輪郭ミル・メートル420件（フル補正へ）
UPDATE FinishMillFeaOperParams
   SET ToolpathCenter = 1
 WHERE ID IN (SELECT FeaOperID FROM FeaOper1 WHERE Units = 1 AND OperationID = 117);
```

**更新後は既存部品の工程を再生成しないと反映されない。**また、
**`ToolpathCenter`を変えたら機械のD番号も同時に変える**こと（フル補正では工具の呼び径を入れる）。
片方だけだと工具半径分ずれる。

**残っている注意点**：輪郭ミルのマッピング420件のうち、リードイン量が10%／25%の行が33件ある
（残り387件は52%）。φ12では10%=1.2mm、25%=3mmで**工具半径6mmに足りず、フル補正では
補正の立ち上げでアラーム041になる**。小さいフィーチャでこれを踏んだら、その行のリードイン量を上げる。

## 軸方向切り込みが分割されない（一撃で深く降りる）ときの見方

**「切り込み量」が工具直径の%指定になっており、その値が残り深さより大きいと分割されない。**

2026-09-11の実例：深さ5mmの領域で、Zが`-4.75`→`-5.0`の2段しか出なかった。
内訳は「総深さ5.0 − 最終切削量0.25 = 4.75を1回で」。切り込み量が工具直径の50%（φ12で6mm）で、
残り4.75mmがそれを下回るため分割されなかった。**深さが6mmを超えていれば分割されるが、
5mmだと一撃になる**という、形状しだいで挙動が変わる危うい状態だった。

このときTechDBの荒加工ミル既定値は`FirstCutAmt_Percent=33.3`／`FinCutAmt=0.5`と正しく設定済みだった。
**部品側のオペレーションが古い値（50%／0.25）を保持していただけ**（TechDB非波及）。
TechDBの値が効いていれば`-4.0`→`-4.5`→`-5.0`の3段になったはず。

**確認方法**：

- CAM画面のオペレーション情報の`First cut:`の値を工具径と比べる
- NCコードなら**Zの段数を数える**。5mm削るのに段が2つしかなければ切り込みが大きすぎる

**ae（径方向の食い込み）も併せて見ること。**同じ実例で、溝幅16mmをφ12で削っていたため
荒加工の1本目は**全幅食い込み（ae＝12mm＝フルスロット）**だった。`ap 4.75mm × ae 12mm`は
アルミだから持っただけで、材料が変われば折れる。**フルスロットでは`ap`を工具径の20%程度まで落とすか、
径方向を分けて2パスにする。**切りくずの逃げ場が無い点も効く。

この負荷はERコレットからの**工具の抜け出し**を起こすのに十分で、
「輪郭仕上げ部だけ底面が一段低い」症状の原因になりうる。

## 回転数が異常な値で出るときは、まず部品の機械定義を疑う

**部品ファイルは機械定義のコピーを内部に持つ。**TechDB側を直しても、既に作られた部品には波及しない
（オペレーションのパラメータと同じ性質）。機械を切り替える前に作った部品は、**古い機械定義のコピーを
抱えたまま**になる。

2026-09-10〜11の実例：CAMツリーの機械が`Mill - Metric`になっていた。
**TechDBの機械一覧にその名前は存在しない**（`Mill - Inch`／`Mill 4,5 axis - Inch/Metric`／`iwashita_NV2`のみ）。
部品に残っていた古いコピーだった。

| 機械名 | 最大主軸回転数 | 工具クリブ |
|---|---|---|
| **iwashita_NV2**（NV2 用に作った機械定義） | **1800** | **4** |
| Mill - Inch ／ Mill 4,5 axis - Inch | 12000 | 5 |
| Mill 4,5 axis - Metric | 12000 | 6 |

**症状**：φ8のHSSセンタードリルに`S12000`が出た。これは切削速度から計算される値ではなく
（Vc=302 m/minという非現実的な値になる）、**機械定義の最大主軸回転数そのもの**。
つまり**上限でクランプされた値**。半端でない丸い数字が出たら上限クランプを疑う。

**さらに重要な含意**：それ以前のプログラムで全工具が`S1800`だったのは、切削条件が正しかったからではなく、
`iwashita_NV2`の上限1800で**すべてクランプされていたから**。
**上限クランプに守られていただけで、フィード/速度テーブルは事実上使われていなかった。**
機械定義を正しくしても、テーブルが未整備なら次は素の値が出てくる。

**対処の順序**：

1. CAMツリーの「機械」をダブルクリックし、`iwashita_NV2`が選ばれているか、最大主軸回転数が何かを確認する
2. 違っていたら選び直す。**機械を切り替えると工具クリブとポストも入れ替わる**ので、
   工具の再割り当てと工程の再生成が要る。切り替え後は必ずポストしてT/H/D番号・座標系・
   工具交換シーケンスが崩れていないか確認する
3. 実機の本当の主軸最高回転数を機械定義に入れる（上限クランプは対症療法）
4. フィード/速度の材質別テーブルを実績値で整備する（これが本筋）

**工具材種の食い違いにも注意。**同じ実例で、工具名は`12MM CRB 2FL 25 LOC`（CRB＝超硬）なのに
オペレーション情報は`Tool material: HSS`と表示されていた。**名前と材質フィールドは別物**で、
切削条件の参照先を決めるのは材質フィールドの方。φ12でS3977（Vc≈150 m/min）は
超硬なら妥当だがHSSでは過大。工具ライブラリの材質と名前を一致させること。

## 実績のある切削条件（実際に削って確認した値）

| 工具 | 被削材 | 回転数 | XY送り | fz | Z送り／リードイン・アウト | 確認条件 |
|---|---|---|---|---|---|---|
| φ12 フラットエンドミル 2枚刃 HSS | アルミ6000番台（A6061等・推定） | 1800 min<sup>-1</sup>（Vc≈68 m/min） | 216 mm/min | 0.06 mm/刃 | 100 mm/min | 軸方向切り込み ap≈4mm で実削り確認済み |

**この種の実績値は「どういう削り方で確認したか」（ap＝軸方向切り込み、ae＝径方向の削り幅、
乾式か切削油か）とセットでないと再利用できない。数値だけ転記しないこと。**

なお、TechDBの初期値は fz=0.0444 / XY=159.84 / Z・リードイン・リードアウト=400 だった。
Z送りの400は水平送りに対して過大なデフォルトなので、**登録時に必ず見直す**こと。

## よく削る材料

- **アルミ6000番台（A6061等）**：主力。削りやすく切りくずの排出も良好
- **ジュラルミン（A2017）**：切削性は良好。6000番台に準じる
- **超超ジュラルミン（A7075）**：たまに使用。硬く発熱が大きいため、
  送り・侵入角ともに条件を落とす。HSSでは特に無理をしない

## NCコードがプランジに見えても、設定ミスとは限らない

**CAMWorksは、工具が閉じた材料に入らざるを得ない場所にしか、らせん／傾斜の侵入を生成しない。**
開いた領域（Y方向の端が抜けている溝、外形の側面など）では、工具は材料の外の空中で真下に降りて
横から切り込む。これが正常な挙動で、NCコードには`G01 Z-○ F○`という**プランジと区別のつかない形**で出る。

つまり**NCコードだけを見て「侵入がプランジのままだ」と判断してはいけない。**
2026-09-10にこれで時間を使った。判別は次の順で行う。

1. **オペレーション側のパラメータを見る**（TechDBではなく、部品のCAMツリーにある工程を右クリック →
   パラメータ編集 → エントリ）。ここが「プランジ」なら設定の問題、「らせん」なら正常な挙動
2. 「らせん」なのにプランジで出ているなら、**ツールパスを画面表示して、最初にZが降りる座標が
   ストックの外か中か**を目視する。外なら空中侵入なので問題なし

**TechDBの既定値は、すでに生成済みのオペレーションには波及しない。**既定値は工程が生成された
瞬間にコピーされるだけなので、TechDBを後から直しても既存の工程は古い設定のまま。
**部品側とTechDB側で食い違うのが普通**だと思っておく。直すならオペレーションで直接変えるか、工程を再生成する。

らせんが物理的に入らない場所でもフォールバックが起きる。判断材料になる既定値は
`らせん半径`（%指定なら工具径に対する割合）と`最小らせん径`の2つ。

なお`エントリ ポイント`欄（「穴の中心にエントリポイント」等）は**らせんを作るかどうかではなく、
らせんを描く位置**を決める設定。プランジの原因にはならない。

## 侵入方法（ヘリカル／ランプ／下穴）

真下に突っ込むプランジ侵入は、エンドミル中心付近の周速がゼロで最も削れないため、
特にHSSでは避ける。代わりに以下を使う。

- **ヘリカル侵入**：らせんを描いて降りる。閉じたポケット向き。
  らせん径が工具径の1倍前後取れる広さが必要
- **ランプ（ジグザグ）侵入**：往復しながら降りる。細長い溝・狭いポケット向き
- **下穴（プリドリル）からの侵入**：最も確実。狭くて上記が使えない場所ではこれ

**侵入角の目安は、材料よりもまず工具材質で決まる。**

| 工具 | 目安 |
|---|---|
| HSS | 3〜6° |
| 超硬 | 5〜15°（メーカー推奨があればそれに従う） |

材料側の補正は、6000番台・A2017は目安どおり、**A7075は浅め（3°前後）に落とす**。

角度を上げるメリットは侵入時間の短縮だけで、デメリットは工具中心部の負荷増と切りくず詰まり。
ap 4mmで1段降りるのに必要な水平移動距離は下記のとおりで、**HSSなら5°前後が実用的なバランス**。

| 侵入角 | 必要な水平距離 |
|---|---|
| 3° | 76mm |
| 5° | 46mm |
| 10° | 23mm |

**狭くて距離が取れない場所は、角度を立てるより下穴を開ける。**
ヘリカルで「らせん1周あたりの下降量（ピッチ）」を指定するUIの場合、
らせん径10mm（円周約31mm）・5°なら1周で約2.8mm下降する。

侵入時の垂直送りは `XY送り × tan(侵入角)` になる（216mm/min・5°で約19mm/min）ため、
Z送りの設定値が上限として効く場面はまずない。

設定はオペレーションのパラメータ側（侵入方法／エントリに相当する項目）で行う。
毎回同じにしたいならTechDBのオペレーション既定値を変える。
