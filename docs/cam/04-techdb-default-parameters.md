# TechDB「デフォルトの操作パラメータ」の設定

`TechDBエディタ → ミル → デフォルトの操作パラメータ` で、オペレーション種別ごとの既定値を決める。
毎回パーツ内で手直ししている設定は、ここを直せば恒久的に不要になる。

## 画面の構造

```
上のドロップダウン   ← オペレーションの種類（荒加工ミル／輪郭／ドリル…）
左のリスト          ← 名前付きパラメータセット。「デフォルト」列に✓が付くものが新規生成時に使われる
右のパネル          ← その中身
```

## 最重要：グレーアウトは「編集禁止」ではない

**グレー＝その値が別の設定に支配されている**というサイン。支配元を変えれば編集できるようになる。
支配元は主に3種類。

| 支配元 | グレーになる項目の例 |
|---|---|
| **パターンの選択**（ポケットアウト等） | 切削の角度（ジグ／ジグザグ用）、最小らせん直径（らせんパターン用）、最初／次のペック量（プランジ荒加工用） |
| **エントリ方法の選択** | 角度（傾斜＝ランプ用。らせんを選ぶとピッチが有効になる） |
| **「工具にリンク」がON** | スピンドル速度・XY送り速度（工具側の値が使われる） |

**支配元を突き止めず、編集したいがためにパターンを変えてはいけない**（削り方そのものが変わる）。

## 項目名と実体の対応（直感的でないので注意）

| 画面の項目名 | 実体 |
|---|---|
| **最大切削量**（深さのパラメータ内） | **ap＝1パスの軸方向切り込み。これが本命** |
| 最初／次のペック量 | **プランジ荒加工専用**。apではない |
| 最終切削量 | 底面に当てる最後の1パスの深さ。薄くすると底面がきれいになる |
| ステップオーバー（側面のパラメータ） | ae＝径方向の削り幅（%は工具径基準） |
| 最小らせん直径（荒加工内） | **らせんイン／アウトパターン**の渦の最小径。侵入とは無関係 |
| らせん半径（フィーチャオプション内） | **らせん侵入の輪の大きさ。侵入の設定はこちら** |
| Z送り速度／リードイン送り速度 | **XY送りに対する%**。工具を変えても自動追従する |
| 最適化 | フィーチャ間を回る順番（削り方ではない）。「最短パス」でよい |

## らせん侵入の設計（重要）

「らせん半径」の**%は工具直径ではなく工具半径が基準**。φ12なら100%＝半径6mm。

- **100%が上限**。これを超えるとらせんの内側に削り残しの島ができ、次のパスで横から突っ込むことになる
- 侵入角は `atan(ピッチ ÷ らせん円周)` で決まる。**らせんを大きくするほど角度が緩くなり負荷が下がる**
  （1周の総切削量は増えるが、1周にかかる時間も増えるので瞬間の負荷は下がる。切りくずの逃げ場も広がる）
- 設定例：φ12・らせん半径80%（4.8mm）→ 直径9.6mm・円周30.2mm、ピッチ3mm → **侵入角5.7°**

エントリ方法の選択肢と意味：

| 選択肢 | 動き |
|---|---|
| らせん | 螺旋を描いて降りる。**通常はこれ** |
| 傾斜 | 斜めに降りる（ランプ）。細い溝向き |
| プランジ | 真下に突っ込む。**HSSでは避ける**（既定値がこれなので要変更） |
| エントリ ドリル | 侵入位置に下穴加工を自動追加。最も安全だが工程が増える |
| エントリ穴 | モデル上の既存穴から侵入 |

## 工具径補正（G41/G42）をどこで有効にするか

**荒加工では「CNC補正：なし」のままが正しい。**径補正は経路を左右にオフセットする機能で、
進入・退出が明確な**輪郭加工でないと成立しない**（ポケットの渦巻き状パスでは破綻する）。
G41/G42は輪郭加工のオペレーション側で設定する。

このため、**残し代0＋仕上げ工程なしにすると、機械側で寸法を微調整する手段が無くなる**。
寸法精度が要る面（ベアリング座・合わせ面・位置決め部）だけ輪郭仕上げ工程を追加し、
そこに0.2mm程度残してG41/G42で追い込む、という使い分けにする。

## 工具径補正（G41/G42）の2方式 — 取り違えると部品が工具半径分ずれる

輪郭加工の`NC → CNC仕上げのパラメータ`で`CNC補正：はい (例: G41/G42)`にすると径補正が出力される。
このとき**すぐ下の「ツールパスの中心」が方式を決めており、機械側のD番号に入れる値が変わる**。

| 方式 | NCコードに出る経路 | 機械のD番号に入れる値 |
|---|---|---|
| フル補正 | 部品の輪郭そのもの | 工具半径（φ12なら6.0） |
| 摩耗補正 | 工具中心の経路（半径分オフセット済み） | 摩耗分のみ（ほぼ0） |

**両者を取り違えると、二重にオフセットされて部品が工具半径分ずれる（または削りすぎる）。**
判別方法は、ポスト出力したNCコードの座標を図面の輪郭寸法と突き合わせること。

**本環境（iwashita NV2 / 現行TechDB）は摩耗補正で確定**（2026-09-10、実機用NCコードで確認）。
判別は荒加工の最内パスと輪郭加工のパスを比べるのが早い。両者の差が**仕上げ代（0.25mm程度）**しか
なければ座標は既に工具中心パス＝摩耗補正。フル補正なら輪郭加工は荒加工より工具半径分（φ12で6mm）
外側を通るため、差が桁違いになる。**機械のD番号には0を入れる**（摩耗が出たらそこで微調整）。
工具半径を入れると片側6mm・溝幅で12mm削りすぎる。

## 工具長補正（G43）の符号：長い工具はプラス

**これは機械（制御装置）側の仕様で、CAD/CAMは無関係。**

直感が外れやすいのは`H`の意味の取り違えによる。**`H`は「工具がどれだけ下に伸びているか」ではなく、
「刃先を指令したZに置くために主軸をどれだけ上げる必要があるか」**を表す。
FANUCの`G43`は「指令値に補正量を**加算**する」と定義されているため、こうなる。

```
G43 Z0 H100  →  主軸のゲージラインが Z+100 へ動く
             →  刃先はゲージラインより100mm下なので、刃先はちょうど Z0
```

工具が長いほど、刃先を同じ場所に置くには主軸を高く上げる必要がある。だから**長い工具ほどHは大きい**。

| 符号を決めるコード | 意味 | 長い工具のH |
|---|---|---|
| **G43** | 工具長補正プラス（加算） | **プラス** |
| G44 | 工具長補正マイナス（減算） | マイナス |

「Gコードによって符号が変わる」の正体はこのG43／G44の違い。CADの銘柄では変わらない。
**本環境のポストは`G43`しか出さない**（`GC(G_LEN_COMP)=43`、`G44`は定義すら無い）ので統一済み。
覚えることは「長い工具はプラス」の1つだけ。

**方式は全工具で統一すること。**工具長補正の入れ方には「工具長そのものを入れる（常にプラスの大きな値）」と
「基準工具からの差を入れる（プラスにもマイナスにもなる）」の2通りがあり、どちらでも正しく動くが、
**混在させるとどれが正しいか分からなくなり事故になる。**
ワーク上面でタッチオフしてG54のZを0にする運用ではHが大きなマイナス値になるが、これも正しい設定。
その場合でも「長い工具ほどHは大きい（マイナスが小さくなる）」という向きは変わらない。

`形状(H)`と`摩耗(H)`は同じ符号規則。工具長は`形状(H)`、実測との微調整は`摩耗(H)`に入れる。

## 症状：アラーム041「G41/G42で切り込み過ぎが発生」

**原因はほぼ確実に、機械のD番号に0以外の値（工具半径など）が入っていること。**
2026-09-10に実機（FANUC 0i-MF）で実際に発生した。

摩耗補正方式ではNCコードの座標が既に工具中心の経路なので、**D値は0が正解**。
ここに工具半径を入れると二重にオフセットされ、リードインの円弧が破綻する。
FANUCの干渉チェックが先読みでこれを検出し、切削に入る前に止める。

**判定の目安**：リードイン円弧の半径よりD値が大きいと確実に出る。
輪郭加工の円弧リードインは工具径に対して小さい半径（実例ではR1.2）なので、
工具半径6.0を入れれば必ず引っかかる。

対処は**オフセット画面のD番号を0にする**（形状・摩耗の両方）。
**プログラム側を書き換えて回避してはいけない。**このアラームは機械が正しく防いでいる。
干渉チェックの無い機械なら、そのまま工具半径分を余計に削って部品が壊れていた。

D値を0にしても`G41`は機能する。実際に削って寸法を詰めるときに0.05のような小さい値を
入れて追い込む、というのが本来の使い方。

## 輪郭加工でプランジを避ける

`輪郭 → 深さのパラメータ → 傾斜` を**オン**にすると、輪郭に沿って斜めに降りる。
オフだと深さの段が変わるたびにリードイン位置で真下に突っ込むため、HSSでは避けたい。
荒加工のらせん侵入に相当する設定。角度は同セクションの「角度」で指定する。

## 径補正使用時のリードイン

- **リードインのタイプは「円弧」にする。**直線リードインは補正の立ち上げでガウジしやすい
- **補正の立ち上げには工具半径以上の移動距離が必要。**既定の「量 52%」は工具直径の52%
  （φ12で6.24mm）で、%指定のため工具径を変えても常に半径をわずかに上回る
- 「ガウジのチェック」は必ずONにする

## 円弧一致（詳細設定 → スプライン出力）

既定はOFF。**ONにすると曲線がG02/G03の円弧として出力される**（OFFだと微小直線G01の連続）。
NCプログラムが小さくなり、制御装置の先読み落ちが減り、面もきれいになる。
曲線の多い形状では効果が大きい。ただしポスト側が円弧出力に対応している必要がある。

## 退避高さ（NC：ラピッド平面／クリアランス平面／フィーチャ間のリトラクト）

段差のある部品では**ラピッド平面の設定ミスが最も衝突に直結する**。4項目の役割は下記。

| 項目 | 役割 |
|---|---|
| ラピッド平面 | 早送り（G00）でXY移動するときのZ高さ。工程間・フィーチャ間の「渡り」の高さ |
| クリアランス平面 | 早送りから切削送りに切り替わるZ高さ（穴あけサイクルのR点） |
| リトラクトストラテジ | 穴あけサイクルで1穴ごとに戻る高さ。ラピッド平面=G98／クリアランス平面=G99 |
| フィーチャ間のリトラクト | フィーチャ間を移るときにどこまで上げるか |

「距離」は基準面からのオフセット。**基準に何を選ぶかが本質**で、
「ストックの上面」＝全フィーチャ共通の絶対高さ、「フィーチャの上面」＝フィーチャごとに上下する相対高さ。

**ラピッド平面の基準を「フィーチャの上面」にしてはいけない。**
深いフィーチャでは渡りの高さも一緒に下がるため、高低差のある部品では衝突する。

退避が低くなる設定は2つあり、どちらもサイクルタイム短縮と引き換えに衝突リスクを負う。

- リトラクトストラテジ＝クリアランス平面（G99）… 穴ごとにフィーチャ上面近くまでしか戻らない
- フィーチャ間のリトラクト＝スキムの距離 … 指定量だけ上がって水平移動する

### 安全側の既定（高低差のある部品ではこれを使う）

```
ラピッド平面          ストックの上面  / 25 mm
クリアランス平面      フィーチャの上面 / 3〜5 mm
リトラクトストラテジ      ラピッド平面 (G98)
フィーチャ間のリトラクト   ラピッド平面（スキムは使わない）
```

25mmの妥当性は**素材上面から測って一番高い障害物より上か**で判断する。削り残す高い部位だけでなく
**バイスの口金・クランプ・ボルト頭・治具**も対象。素材上面より高く出るクランプがあれば足りない。

### 運用上の注意

- この設定は**オペレーション単位**。1つ直しても他には波及しない。「セットアップの定義を使用」に
  チェックするとセットアップ側の1か所で統一できるが、**セットアップ側の値が低いと逆効果**なので
  チェック前にそちらの値を確認する。恒久化するならTechDBのオペレーション既定値側に入れる
- ラピッド平面が守るのは**工具先端**。ホルダ・チャックの干渉は別途確認が必要
- 工具交換時の退避（G28）はこの設定ではなく**ポスト側**の管理

## 荒加工ミルに設定した既定値（2026-08-31時点）

```
Z送り速度            45 %      （XY送りに対する比率。実績 216→100 に相当）
リードイン送り速度    50 %
コーナーでのスローダウン ON（80%）
パターン             ポケット アウト   （切りくずが外へ逃げる／切削方向を一定に保てる）
クリーンアップ パス   OFF
側面の残し代          0 mm      （荒加工のみで仕上げる前提）
ステップオーバー      40 %      （ae＝4.8mm）
切削方法             ダウンカット（ジグザグOFF）
深さ処理             領域ごとの深さ（レベル順より侵入回数が少なくHSS向き）
最大切削量           30 %      （ap＝3.6mm。実績4mmとほぼ同等）
最終切削量           0.5 mm
エントリ             らせん／半径80%／ピッチ3mm → 侵入角5.7°
CNC補正             なし      （径補正は輪郭加工側で）
最適化               最短パス
```

## ドリルの既定値（2026-08-31時点）

```
ドリルのタイプ      ペック加工（G83）  ← アルミは切りくずが繋がるため毎回完全に抜くG83が安全
最初のペック量      5 mm    ← %指定に変えるとドリル径に追従する（推奨：最初100% / 次70%）
次のペック量        2 mm
ドエル             0
ペック クリア量     0.254 mm  ← 0.01インチの変換値。0.5mm等に丸めてよい
キャンドサイクル出力 ON      ← OFFにすると上下動が全部座標で展開されプログラムが膨大になる
リトラクトストラテジ ラピッド平面(G98)  ← 下記の判断待ち
```

ドリルのタイプとGコードの対応：

| 選択肢 | Gコード | 備考 |
|---|---|---|
| ドリル加工 | G81 | 浅い穴なら最速 |
| ペック加工 | G83 | 毎回R点まで完全に抜く。**アルミの既定はこれ** |
| 高速ペック加工 | G73 | 少しだけ戻る。速いが切りくずが抜けきらない |
| 可変ペック加工 / ガンドリル加工 | — | 標準サイクルに対応しない場合あり |

**穴あけのリトラクト（G98 / G99）はサイクルタイムに直結する。**
G98はラピッド平面（ストック上面+25mm）まで、G99はクリアランス平面（フィーチャ上面+3mm）まで戻る。
穴が多いほど差が開くが、**穴と穴の間にクランプ・リブ等の障害物があるとG99は衝突する。**
段差の少ない面にまとまった穴はG99、面をまたぐ場合はG98、という使い分けにする。

なお、`0.254mm = 0.01インチ` のように、**メートル法のTechDBにもインチ由来の変換値が残っている**
箇所がある（元がインチ設計のため）。実害はないがキリの悪い数値を見たらこれを疑う。

## 【今後のタスク】径補正を摩耗補正からフル補正へ切り替える

**目的**：機械のオフセット画面で「形状」に工具の呼び径（半径または直径）を入れ、「摩耗」に摩耗分を
入れて寸法を追い込む、という一般的な運用にする。現状は摩耗補正のため形状にも0を入れており、
本来の使い方になっていない。

**これはポストプロセッサではできない。CAM側の設定である。**
ポストはCAMから渡された座標とD番号をそのまま出力するだけで、経路をどちらの方式で計算するかはCAMが決める。

**変更する設定**：輪郭ミルの`NC → CNC仕上げのパラメータ → ツールパスの中心`
（TechDB内部の列名は`ToolpathCenter`、テーブルは`DefPrmFinishMillFeaOperParams`）。

| 選択肢 | DB上の値 | NCに出る経路 | 機械の形状(D)に入れる値 |
|---|---|---|---|
| 補正あり（With compensation） | 2 | 工具中心の経路 | 0（摩耗分のみ）＝**現状** |
| 補正なし（Without compensation） | 1 | 部品の輪郭そのもの | 工具の呼び径＝**移行先** |

**作業手順**：

1. TechDBの輪郭ミル「デフォルトの操作パラメータ」で「ツールパスの中心」を「補正なし」にする
   （2026-09-10時点でDBを見た限り、メトリックの既定レコード`FeaOperID=87`は既に`1`になっていた。
   要確認）
2. **部品側の既存オペレーションを個別に変更するか、工程を再生成する。**
   TechDBの既定値は生成済みのオペレーションに波及しないため、1だけでは変わらない
3. ポストして**NCコードの座標が図面の輪郭寸法と一致すること**を確認する
   （現状は工具半径分ずれている。これが一致すればフル補正になっている）

**TechDBのどこに`ToolpathCenter`があるか（2026-09-10に全テーブルを調査）**

2系統あり、**数の多い方はUIでは直せない**。

| 場所 | 対象 | 件数 | 当時の設定 |
|---|---|---|---|
| デフォルトの操作パラメータ（UIで編集可） | 輪郭ミル メートル `ID=87` Default | 1 | **補正なし（フル）** |
| 同上 | 輪郭ミル メートル `ID=145` Contour machining | 1 | 補正あり（摩耗） |
| 同上 | 輪郭ミル メートル `ID=146` Contour and floor machining | 1 | 補正あり（摩耗） |
| 同上 | 輪郭ミル インチ `ID=67/118/119` | 3 | 補正あり（摩耗） |
| フィーチャと操作のマッピング | 輪郭ミル メートル | **420** | 全部 補正あり（摩耗） |
| 同上 | 輪郭ミル インチ | 418 | 全部 補正あり（摩耗） |
| ねじ切り・タップ系 | `DefPrmThreadMill`4／`ThreadMill`95／`MSHoleThreadMill`3／`TapFinishMill`1565 | 1667 | 全部 補正あり（摩耗） |

**メートル系で`Default`だけが補正なしで、名前付きストラテジが補正あり**というちぐはぐな状態だった。
輪郭加工で「Contour machining」を選ぶと摩耗補正の経路が出る。

「フィーチャと操作」側（420件）は`FeaOper1`テーブルから`FinishMillFeaOperParams`が参照される構造で、
**工程の自動生成時に使われる**。UIで1件ずつ直すのは非現実的なので、一括で直すならSQLで更新する
（SOLIDWORKS終了状態＋`TechDB.cwdb`のバックアップ必須）。

ただし**TechDBを完璧に統一しなくても、オペレーション側さえ正しければ正しいツールパスが出る。**
最終的にNCを決めるのはオペレーションの値。

**移行時の注意（実機側）**：

- **形状(D)に入れるのは半径か直径か。**FANUCはパラメータで切り替わる。
  **iwashita NV2は直径指定であることを2026-09-10に確認済み**（φ12なら`12.0`を入れる。半径の6.0ではない）。
  **摩耗欄も直径基準**なので、片側0.05mm削り足したいなら摩耗に入れるのは0.1（直径で0.1＝片側0.05）
- **内角のRが工具半径より小さい形状はフル補正では加工できず、アラーム041になる。**
  摩耗補正では出なかった制約が新たに付く。設計側で内角Rを工具半径以上にしておく必要がある
- リードインには補正を立ち上げるための助走距離（工具半径以上）が必要。既定の「量52%」なら自動的に満たす

## 併せて確認すること（TechDB側）

- [ ] ツールクリブが参照している工具が意図した材質か。
      主要パラメータの`CRB`は**超硬（Carbide）**、`HSS`はハイス。
      `12MM CRB 2FL 25 LOC` = φ12・超硬・2枚刃・刃長25mm。
      HSSを登録したつもりで標準ライブラリの超硬エントリを参照していないか
- [ ] ステーション番号が0のまま放置されていないか（1〜ステーション合計の範囲で設定する）
- [ ] クーラントOFFが**全材質のレコード**に反映されているか（工具×材質のレコード単位で
      管理されているため、6000番台でOFFにしてもA7075のレコードは別。
      前提として`機械の定義→ポスティング→クーラントの定義元`が「工具」であること）
- [ ] `Tool Crib 1 (Metric) Empty` が `iwashita_NV2` マシンの既定クリブになっているか
      （なっていないと、登録した工具が新規パーツで選ばれない）
- [ ] 輪郭ミルで「傾斜＝角度」にした場合、**クリーンアップパスがONのままか**
      （荒加工とは逆。傾斜で降りると壁に螺旋状の削り残しが出るため、後始末のパスが必須）
