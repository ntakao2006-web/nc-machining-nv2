# はじめての人向け: AI エージェントでこのリポジトリを使う

README の「AI に聞きながら使う」を、もう少し詳しく説明したページです。GitHub も AI も初めての人を想定しています。
Claude・Codex・Antigravity など、どの AI エージェントでも同じ流れで使えます。

> 画面の表示や料金は変わることがあるので、つまずいたら各サービスの公式サイトで確認すること（2026年11月時点の内容）。
> 実際にたどってつまずいた所があれば、直して記録してください。

## 使い方は3段階ある

| 段階 | できること | 必要なもの |
|---|---|---|
| ① 読むだけ | ブラウザで資料を読む | なし（リンクを開くだけ） |
| ② AI に聞く | 日本語で質問し、根拠付きで答えてもらう | AI エージェントのアプリ |
| ③ 記録する | 分かったことを AI に書かせ、GitHub に残す | ②＋GitHub アカウント＋書き込み権限 |

**このリポジトリは公開されているので、①と②は誰でもすぐにできます。** ③は続けて記録する人だけでかまいません。

## 言葉の意味（最低限）

| 言葉 | 意味 |
|---|---|
| リポジトリ | ファイルと、その変更履歴をまとめて入れておく箱。このページ全体がひとつのリポジトリ |
| AI エージェント | 自分の PC のフォルダの中身を読んだり、コマンドを実行したりできる AI。Claude の「Code」、Codex、Antigravity など |
| クローン | リポジトリを自分の PC にコピーすること。AI に頼めばやってくれる |
| プル | GitHub にある最新の内容を、自分の PC に取り込むこと |
| コミット | 「ここまでの変更」を、説明を付けて履歴に記録すること |
| プッシュ | 自分の PC で記録したコミットを GitHub に送り、他の人にも見えるようにすること |
| NotebookLM | Google の AI ノート。入れた資料（ここではファナックのマニュアル）だけを根拠に答えてくれる |
| `AGENTS.md` | AI に向けて「このリポジトリではこう動け」と書いたルールのファイル。AI はまずこれを読む |

## ① 読むだけ

https://github.com/ntakao2006-web/nc-machining-nv2 をブラウザで開き、README の目次から読みたいファイルをクリックします。
機械を動かす前に、最低限 [`docs/machine/operation.md`](../machine/operation.md) は読んでください。

## ② AI に聞く

### 準備するもの

AI エージェントのアプリを1つ用意します。どれでもかまいません。

| AI | 使うもの | ルールの読み方 |
|---|---|---|
| Codex | ChatGPT デスクトップアプリの Codex（慣れたら CLI や VS Code 拡張でもよい） | `AGENTS.md` を自動で読む |
| Claude | Claude デスクトップアプリの「Code」タブ（https://claude.ai/download ） | `CLAUDE.md` を自動で読み、そこから `AGENTS.md` を読む |
| Antigravity | Google Antigravity でフォルダを開く | `AGENTS.md` を自動で読む |
| そのほか | 各アプリでフォルダを開く | 最初に「`AGENTS.md` を読んで」と伝える（下の始め方の文に入っている） |

- **お金をかけずに試すなら Codex。** ChatGPT の無料プランでも、使用上限つきで使える（2026年11月時点）。ほかの AI も含め、料金や上限は変わるので公式サイトで確認し、費用をどうするかは先生や班で事前に相談する
- Windows で使うのに、WSL などの追加の準備は要らない
- **クラウド版（ブラウザ上で動く Codex など）は、GitHub アカウントとの連携が必要になる。** 最初は PC のアプリで使うのがおすすめ
- AI がクローンするには、PC に **Git** が入っている必要がある。入っていなければ、下の「Git がないとき」に進む

### 始め方

1. 作業用の空のフォルダを作る（例: `ドキュメント\nc-machining-nv2`）
2. AI のアプリで、そのフォルダを開く
3. 次の文をそのままコピーして送る

```
https://github.com/ntakao2006-web/nc-machining-nv2 をこのフォルダにクローンして。
クローンしたら AGENTS.md と README.md を読んで、そのルールに従って私の質問に答えて。
```

4. AI が「コマンドを実行していいですか」「インターネットを使っていいですか」と聞いてきたら、何をするのか確かめてから許可する。**「常に許可する」設定や、安全のための制限（サンドボックス）を外す設定にはしない**
5. コピーが終わったら、**同じフォルダで新しいチャットを始めて**質問する。新しいチャットでは、AI がルール（`AGENTS.md`）を自動で読み込んだ状態になる（会話の途中でコピーしたファイルは、自動では読み込まれないことがある）

### Git がないとき

**続けて使う人・③の記録もしたい人は、Git を入れる。**

1. https://git-scm.com/ から Git for Windows をダウンロードしてインストールする（インストール画面の選択肢は、基本的にそのままでよい。GitHub へのサインインに使う道具も一緒に入る）
2. AI のアプリを一度閉じて、開き直す
3. 「始め方」の 3 からやり直す

**読んで質問するだけなら、ZIP でもよい。**

1. https://github.com/ntakao2006-web/nc-machining-nv2 をブラウザで開く
2. 緑色の「Code」ボタン →「Download ZIP」
3. ZIP を展開し、できたフォルダを AI のアプリで開いて、新しいチャットを始める
4. 「AGENTS.md と README.md を読んで、そのルールに従って私の質問に答えて」と送る

この方法だと、③の記録はできません（GitHub とつながっていないため）。

### 2回目から

- 同じフォルダを開いて新しいチャットを始め、最初に「最新の状態にして」と送る。他の人が足した記録が取り込まれる
- ZIP で始めた人は、ZIP をダウンロードし直す

### ファナックのマニュアルを調べたいとき

マニュアルはこのリポジトリには入っていません。仲間うちで共有している **NotebookLM** に入っているので、管理者に共有を頼み、そこで質問して辞書のように引きます（[`docs/machine/manuals.md`](../machine/manuals.md)）。
AI エージェントに聞いて「NotebookLM で『〇〇』と聞いてください」と言われたら、その文を NotebookLM に貼ってください。
NotebookLM の答えを AI エージェントに伝えるときは、答えに付いている**マニュアルの名前とページ**も一緒に貼ってください（AI が、機種違いや読み違いに気づけるように）。

### 上手な聞き方

- **やりたいことと状況を書く**: 「φ10 のエンドミルでアルミの溝を削りたい。深さは 5mm。条件の決め方を教えて」
- **分からなかったら聞き返す**: 「もっと簡単に説明して」「その言葉はどういう意味？」
- **根拠を確かめる**: 「根拠はどのファイルのどこ？」と聞いて、その部分を自分でも読む

## ③ 記録する

### 書き込み権限をもらう（最初の1回だけ）

1. https://github.com/signup で GitHub のアカウントを作る（**卒業後も使うなら個人のメールがおすすめ**）
2. ユーザー名をこのリポジトリの管理者に伝え、「書き込み権限（Collaborator）をください」と頼む
3. 招待メールが届いたら「Accept invitation」を押す
4. PC に Git for Windows が入っていれば、特別な設定は要らない。**初めて記録を送るときに、ブラウザで GitHub へのサインインを求められる**のでサインインする（次からは自動）
   - **パスワードやアクセストークンを、AI のチャットに貼らない**
   - うまくいかなければ「GitHub にプッシュできるように設定したい。手順を1つずつ教えて」と AI に聞く

### 記録の流れ

1. 「〇〇したら〇〇になった。記録して」と AI に頼む
2. AI が、どのファイルに何を書くか・送り先を見せて「記録していいですか」と聞いてくる → **内容を読んでから OK する**
3. AI が GitHub に送る（コミット・プッシュ）→ 他の人にも見えるようになる
4. 送れなかったときは、AI が原因（サインイン・ネットワーク・権限など）を調べて教えてくれる。権限がないと言われたら、上の「書き込み権限をもらう」か、下の Issue の方法を使う

**どのファイルに書けばいいかを自分で覚えておく必要はありません。** ルールは [`AGENTS.md`](../../AGENTS.md) に書いてあり、AI はそれに従って書きます。

### 権限がない人が、どうしても残したいとき

AI に「記録したい内容を、Issue に貼れる文章にまとめて」と頼み、
GitHub のこのリポジトリの「Issues」→「New issue」に貼ってください（GitHub アカウントが要ります）。管理者が取り込みます。
**Issue も誰でも読めます。** 人の名前や学校の内部情報を書かないでください。

### TechDB やポストを直したとき

TechDB はメーカーのサンプルデータを含むため、このリポジトリには入れず、管理者が仲間うちで手渡ししています。
直したときの扱いは [`config/README.md`](../../config/README.md) の「更新したとき」に従うか、
AI に「TechDB（またはポスト）を更新した。どうすればいい？」と聞いてください。

## 気をつけること

1. **AI の答えをうのみにしない。** 特に工作機械の操作・パラメータ・切削条件・工具の補正値は、**根拠を確認し、実機ではシングルブロック・オーバーライド0で確かめる。** 間違えると工具・ワーク・機械がぶつかる
2. **機械のパラメータを AI の提案だけで変えない。** 何のためにどのビットを変えるのかを理解してから変え、変えたら必ず記録する（機械側には履歴が残らない）
3. **このリポジトリは公開されている。** 人の名前・メールアドレス・学籍番号・学校の内部情報を記録させない。「〇〇班」「〇〇担当」のように役割名で書く（AI もそうするように設定してある）
4. 写真やファイルを足すときは、**人の顔・名前・PC のユーザー名が写り込んでいないか**確認する
5. 分からなくなったら「最初からやり直したい」「今どういう状態？」と AI に聞けばよい

## 管理者を引き継ぐとき

このリポジトリは、NV2 を使う人がいる限り続けて使う前提です。管理者が卒業する前に:

- 次の管理者を決め、GitHub の Settings → Collaborators から招待し、**リポジトリの所有権を移す**（Settings → Transfer、または Organization に移す）
- [`config/`](../../config/README.md) のポストが最新か確認し、古ければ更新してコミットする
- **手渡し用の最新の TechDB（`TechDB.cwdb`）と、共有している NotebookLM の管理を、次の管理者に渡す**（どちらもリポジトリには入っていないので、渡し忘れると失われる）
- [`docs/machine/parameters.md`](../machine/parameters.md) の「未確認・要追記」を見直し、分かっていることを書き足す
