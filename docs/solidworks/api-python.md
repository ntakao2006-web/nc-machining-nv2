# Python から SolidWorks を操作する（SolidWorks API）

NC加工ではないが、SolidWorks まわりの知見としてここに置く。
Python（pywin32）から、起動中の SolidWorks の部品を読んだり、新しい部品を作ったりできる（2026-09-28 に確認）。
形状を読み出して別の形式に変える実例は [`gerber-export.md`](./gerber-export.md)。

## ⚠️ 始める前に：保存していない作業がないか確かめる

**2026-09-28、起動中の SolidWorks に API で新しい部品を作って閉じた直後、SolidWorks が落ちた**（原因は分かっていない）。

- API で操作する前に、開いているファイルをすべて保存する
- 落ちたあとに API から呼ぶと、**画面の出ない別の SolidWorks が裏で起動する。** 作業が終わったら終了させる
- 落ちると、CAM などのアドインの設定が消えることがある（[`addin-disappears.md`](./addin-disappears.md)）

## つまずいた点と対処

| つまずき | 対処 |
|---|---|
| メソッドを呼ぶと「メンバーが見つかりません」になる | pywin32 の既定の呼び方（動的バインド）では、メソッドとプロパティの区別が崩れる。SolidWorks のインストール先にある `sldworks.tlb` を `gencache.EnsureModule` で読み込み（早期バインド）、各オブジェクトを `モジュール.IModelDoc2(obj._oleobj_)` のように、使いたいインターフェースで包み直す |
| PowerShell から操作しようとして失敗する | Python から操作する |
| 押し出しが、エラーも出ずに失敗する | 円弧を描くとき（`CreateArc`）の回転方向が逆で、円弧が大回りになっている。押し出す前に、スケッチを `Select2` で選んでおくことも必要 |
| 材料が設定されない | 材料名は、材料ライブラリの名前と**表示されている言語の名前**で指定する。日本語版の例：`SetMaterialPropertyName2("", "solidworks materials", "炭素鋼(普通)")` |
| 押し出しの向きが思ったのと違う | 「正面」の平面がモデルのどの軸を向いているかは、**部品テンプレートによって違う。** 下の「基準面の向き」の節を参照。スクリプトでは、面を名前ではなく法線の向きで選ぶ |
| `EnsureDispatch("SldWorks.Application")` が「makepy を自動で作れない」で止まる | `sldworks.tlb` を `pythoncom.LoadTypeLib` で読んで、その番号で `gencache.EnsureModule` する（`tools/solidworks-api/sw_helpers.py` の先頭） |
| `ISketch.ModelToSketchTransform` でモデル座標をスケッチ座標に直すと、値がおかしい | pywin32 から `IMathUtility.CreatePoint` 経由で使うと、(20, 15) が (20, 0) になった。基準面の `IRefPlane.Transform` の中身（面内の X'・Y' 軸と原点）から自分で計算する |
| SOLIDWORKS の体積・外形の値が、計算と少し合わない | `CreateMassProperty` の体積や `GetBodyBox` の外形は**概算**で、外形は 0.1 mm ほどふくらむことがある。正確な寸法は STEP に書き出して、FreeCAD などで測る |

## 基準面の向き（Z が上の部品テンプレート）

SOLIDWORKS 2025 から、部品テンプレートで上向きの軸を Y か Z から選べるようになった。
SOLIDWORKS 2026 で Z を上にしたテンプレートを、API で調べた結果は次のとおり（2026-11-14 に確認）。

| 基準面 | 法線（面に垂直な向き） | その面にスケッチしたときの横軸 → 縦軸 |
|---|---|---|
| 正面 | +X | +Y → +Z |
| 平面 | +Z | +Y → −X |
| 右側面 | +Y | −X → +Z |

- **「正面」にスケッチして押し出すと、厚みが X の向きに付く。** Y が上の昔ながらのテンプレート（正面の法線が +Z）とも、FreeCAD（正面は −Y から見る XZ 面）とも違う
- **「平面」（XY 平面）にスケッチしても、スケッチの横軸はモデルの +Y になる。** スケッチ上で横に 40 mm 描くと、モデルでは Y 方向に 40 mm になる
- Z が上なので、NC加工の座標（Z が主軸の向き）とは合わせやすい
- テンプレートの向きは PC ごと・人ごとに違いうる。**自分のテンプレートは、手で1つ作るか、`sw_helpers.planes(model)` で向きを確かめる**

## AI エージェントに部品を作らせる（スクリプト＋別のソフトで検算）

AI エージェント（Claude Code など）に SOLIDWORKS で部品を作らせるときは、
**エージェントが Python のスクリプトを書き、それを実行して SOLIDWORKS に形を作らせる**のが確実だった（2026-11-14 に確認）。
道具は [`tools/solidworks-api/`](../../tools/solidworks-api/) にある。使い方は [`tools/README.md`](../../tools/README.md)。

1. 寸法をスクリプトの先頭に数値でまとめる
2. スクリプトが SOLIDWORKS にスケッチと押し出し・カットを作らせる。**スケッチは毎回、寸法つきの完全定義にする**（下の節）
3. SLDPRT と STEP に書き出す
4. STEP を **FreeCAD など別のソフトで読み直して**、外形・体積・穴の位置と径を測る
5. 最後に人が SOLIDWORKS で開いて確かめる。フィーチャーと寸法が残っているので、そのまま手で直せる

- 作業中は SOLIDWORKS の画面が開く（マウスやキーボードは使わない）。上の「始める前に」のとおり、開いているファイルは先に保存しておく
- **書き出した STEP は必ず読み直して測る。** 2026-11-14 に1度、SOLIDWORKS の中では開いている横穴が、STEP には入っていなかった（STL には入っていた）。ファイルを開き直してから書き出すと入った。原因は分かっていない
- スケッチを描くときは、点がスナップや自動の拘束でずれないよう `ISketchManager.AddToDB = True` にする

### スケッチを完全定義にする

寸法を付けずに数値で線を置いただけだと、スケッチは「未定義」のままで、あとで何かの拍子に形がずれるおそれがある。
次のやり方で、すべてのスケッチを完全定義にできた。

| やること | 方法 |
|---|---|
| 大きさ（径・幅・高さ）の寸法 | `ISketchManager.FullyDefineSketch` に任せる |
| 原点にある点・中心矩形の中心 | 先に原点へ一致・中点の拘束で留める（自動寸法は、原点から距離 0 の物を留めてくれない） |
| 原点から離れた点の位置（穴の中心など） | `AddHorizontalDimension2`・`AddVerticalDimension2` で、原点からの寸法を明示的に付ける |

- `FullyDefineSketch` の基準（datum）に `None` を渡すと、何も付かずに終わる。原点の点（`Point1@原点`）を選んで、そのオブジェクトを渡す
- `AddToDB = True` のまま `FullyDefineSketch` を呼んでも、何も付かない。呼ぶ間だけ `False` にする
- 原点を基準に渡しても、離れた点の位置には寸法が付かないことが多かった。だから位置は自分で付ける
- 寸法を付けるたびに出る「寸法値の入力」の小窓は、`swInputDimValOnCreate` の設定を一時的に切って止める（終わったら元に戻す）
- 完全定義になったかは `ISketch.GetConstrainedStatus()` が 3 かどうかで確かめる

## 他人が作ったツール（MCP サーバー・スキル・マクロ）を入れる前に

SOLIDWORKS を AI から動かすための MCP サーバー（AI と外部のソフトをつなぐための仕組み）は、有志が作ったものがいくつも公開されている。
**SOLIDWORKS の公式のものはない**（2026-11-14 時点）。

- こうしたツールは、SOLIDWORKS を自由に操作でき、PC の中のファイルも読める。**中身を確かめずに入れない**
- AI に読ませる説明文（README や SKILL.md）に、AI への指示が紛れ込ませてあることがある（プロンプトインジェクション）。入れる前に検査ツールにかける
  - 例：NVIDIA の SkillSpector（スキル・MCP の設定を、入れる前に調べる）。**英語以外の文章、画像の中の文字は調べられない**と説明されている。何も見つからなくても安全の証明にはならない
- 上の手順のように、自分たち（またはエージェント）がその場で書いたスクリプトで動かせば、他人のコードを入れずに済む
